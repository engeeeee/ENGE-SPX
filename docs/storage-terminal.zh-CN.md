# 存储位置与第三方终端

在「偏好设置」中配置终端和存储，在顶部「SSH」管理远程连接。

## 选择终端

自动模式为 Claude Code / Codex 使用[智能粘贴终端](smart-clipboard.zh-CN.md)，在 CLI 当前输入区接收 Ctrl+V 文字、截图及文件。显式选择 Windows Terminal、PowerShell 或自定义 exe 时继续使用外部终端，只保留它们原有的剪贴板功能；不修改全局快捷键。Linux shell/登录窗口的自动选择保持原行为。

自动选择依次检测 **Windows Terminal → PowerShell 7 → Windows PowerShell**。不会自动寻找、优先选择或安装第三方终端。手动选定的终端找不到时会提示，不会静默切换。

1. 在“工作区终端”选择内置终端类型，或选择 **自定义程序** 并指定任意第三方终端的 exe。
2. 自定义程序按该终端官方说明填写启动参数，必须包含一次独立的 `{command}`。软件不根据 exe 名称猜测参数。
3. 点击“测试终端”，在所选终端内打开本地 PowerShell 测试窗口，不需要代理、账号或 Docker 工作区。
4. 确认可用后点击“保存终端”。随后 Claude Code、Codex、Linux 终端和登录窗口使用同一设置，无需重新建立代理连接。

终端只负责 Windows 上的显示与交互，工具继续在 Linux 容器内运行。`spx claude` 等命令行操作继续使用调用它们的终端。

新自定义配置仅提供 `{command}` 占位符，不假定各终端的命令行选项相同。对支持 `-e` 的终端，参数可以是：

```text
-e {command}
```

另一些终端使用 `start --cwd "{project}" -- {command}` 等形式；具体以所选程序的帮助为准。项目目录同时作为启动进程的工作目录传入；需要窗口标题或额外控制时使用该终端支持的参数。

0.8.4 取消旧版的 Pebrel 专用入口及自动优先发现。已有 `kind=pebrel` 设置在读取时规范为通用自定义配置，保留原 exe 和原来实际使用的参数；保存后使用普通 `kind=custom`，无需重建工作区。兼容读取不代表新配置对该终端有特殊优先级。

## 启动指令出现在 AI 输入栏

某些终端会向每个新会话自动输入欢迎页或系统信息命令。直接启动 Docker / CLI 时，这些内容可能进入 Claude Code 或 Codex 的输入框。在所选终端关闭自动欢迎命令或启动输入，或者使用默认的标准终端。ENGE SPX 不注入欢迎指令，也不通过自动回车、吞掉输入或修改第三方全局设置来处理。

例如用户报告的 `Clear-Host; & '...nebula_fastfetch_intro.ps1'` 来自终端自己的欢迎页，其注入行为可在 [Pebrel 源码](https://github.com/Kuddev/pebrel/blob/0ed1a041a21681022b984546c926e15de8688d7e/nebula_app/src/gpui_shell/terminal/view/startup.rs#L212)核对。这是通用启动输入冲突的一个已核实例，不为它增加专用运行分支。

| 占位符 | 用途 |
| --- | --- |
| `{project}` | 本机所选项目的完整路径 |
| `{title}` | 工作区窗口标题 |
| `{command}` | 必须独立出现一次，插入完整 Docker 命令及各个参数 |

参数按 Windows 双引号规则解析，不会自动拼接成 CMD 命令。exe 路径使用上方独立输入框，不要填进参数。含空格的参数请加双引号。

## 智能终端快捷输入

点击智能终端顶部的 **快捷输入**，或按 **Ctrl+Shift+P**。输入名称或内容筛选，用方向键选择，按 **Tab** 或 **Enter** 将选中内容填入当前命令行或 AI 草稿。回到终端后按 Enter 发送。

在 SSH 和 Linux Shell 的命令行输入常用指令的开头，例如 `git st`，灰色后缀会跟在光标后面。按 **Tab** 填入后缀，再按 **Enter** 执行。没有灰色提示时，Tab 由原 Shell 处理。提示使用内置指令和「快捷输入」中保存的 Shell 指令。

通过「添加」「编辑」保存常用单行命令或提示词。SSH 与 Linux Shell 使用命令列表，AI 编程工具使用提示词列表。偏好随应用数据迁移。灰色补全适用于回显输入、支持括号粘贴的 Shell 提示符，也可识别 OSC 133 或 OSC 633 的输入区标记。[Shell 集成序列](https://learn.microsoft.com/zh-cn/windows/terminal/tutorials/shell-integration)

## SSH 连接及文件粘贴

在 Windows 打包版的「SSH → 新建机器」或「编辑」中可选填密码或私钥口令。凭据由当前 Windows 用户的 DPAPI 加密保存。双击已保存的机器或点击「连接」直接打开终端，首次连接仍需核对主机指纹。需要多因素认证时可留空并按终端提示操作。「临时连接」也可填写密码，凭据只在本次会话使用。

编辑时可勾选「清除已保存的凭据」。留空会保留原凭据，更改服务器、端口、用户或私钥时需要重新填写。退回 0.15.13 前，可先清除全部 SSH 机器的已保存凭据，使机器列表恢复为旧版可读格式。

在 Windows 复制截图或文件后，在当前 SSH 终端按 **Ctrl+V** 或右键。系统 SFTP 客户端连接所选地址并核对已知主机密钥，上传到该远端账户的 `.enge-spx-paste-*` 目录，成功后将路径填入输入区。密码认证或加密私钥需要在连接表单填写相应凭据。远端需要启用 SFTP，并允许在主目录创建目录与设置权限。每个文件最多 128 MiB，一批最多 256 MiB。成功上传的文件保留在远端账户下，可按需删除。

Windows 打包版 SSH 使用随包的微软 ConPTY 组件保留 Codex 区域滚动过的历史。行内模式可用滚动条回看最近 10,000 行。Codex 全屏模式的对话由 Codex 管理，滚轮操作交给其对话视图。Windows 源码运行可先执行 `python tools/prepare_windows_conpty.py` 准备相同组件。

## SFTP 文件管理

在 SSH 页面选择一台已保存的机器并点击 **SFTP 文件**，或用 **临时 SFTP** 输入连接信息。已打开的 SSH 终端顶部也有 **SFTP 文件** 入口。

- 双击文件夹浏览，双击文件或点「下载文件」选本机保存路径。
- 「上传文件」可多选本机普通文件，文件会传到当前远端目录。
- 可输入远端路径、返回主目录或上一级、刷新和新建文件夹。上传下载都会显示进度，可取消。

文件管理器通过系统 OpenSSH 连接所选服务器的 SFTP 子系统。首次直接连接要核对主机指纹，已保存的密码或私钥口令可用于此连接。正常关闭窗口时结束文件连接。上传使用远端临时文件，完成后移到目标名称，下载完成后才生成最终文件。遇到同名文件时请选择其他名称。意外断线时，服务器可能保留以 `.enge-spx-upload-` 开头的 `.part` 文件。[SFTP v3](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02)

## 占用空间的位置

| 数据 | 内容 | 迁移入口 |
| --- | --- | --- |
| 应用数据 | 配置、代理信息、日志、运行环境下载缓存及断点文件 | 应用数据与下载缓存 |
| Docker 数据盘 | 镜像、构建缓存、容器可写层、工具账号与浏览器数据卷 | Docker 数据盘迁移助手＋Docker Desktop |
| 项目目录 | 选择的真实项目文件 | 在 Windows 中自行整理，再重新选择项目 |
| 程序目录 | ENGE SPX 的 exe 和运行库 | 安装时选择目录，或将完整免安装包放在目标盘 |

应用数据和 Docker 数据盘使用不同的专用文件夹，例如 `D:\ENGE-SPX\data` 和 `D:\DockerData`。不要直接选择整块磁盘，也不要选择已有项目目录。

## 清理运行环境下载缓存

运行环境包在导入并完成镜像核验后自动清理。以 0.15.12 的环境包为例，一份下载副本约占 835 MiB。准备失败或暂停时，下载文件保留供重试。

在「偏好设置 → 存储 → 运行环境下载缓存」可检查和清理旧包及已导入的完整副本。续传文件和本版本待导入的下载包保留。已安装镜像、账号和浏览器资料在 Docker 数据盘中，容量可在 Docker Desktop 中查看。

## 迁移应用数据与下载缓存

1. 保存工作。在“应用数据与下载缓存”选择或输入专用空目录。
2. 点击“检查并迁移应用数据”，核对当前路径、目标路径、大小和可用空间，再确认。
3. 等待复制和校验完成。软件会停止本工作区和后台服务，保留安装标识，切换默认位置，再清理原目录中已校验的副本。
4. 当前位置会更新为新目录。重新检查并确认连接，继续使用工作区。

后续运行环境下载进入新目录，已有 `.part` 和续传元数据一起迁移。Windows 下会先为目标设置当前用户、SYSTEM 和管理员的访问权限，再写入配置。请使用支持 Windows 文件权限的本地磁盘。

原目录保留很小的 `relocated.json` 和锁文件，让旧的 `--data` 启动方式能找到新位置；LocalAppData 下的 `ENGE-SPX-location.json` 记录默认位置。少数被其他进程占用的旧文件无法删除时，会在新目录的 `storage-migration.json` 中记录。

迁移不会重新安装镜像或项目容器。下次检查连接时，只重建需要更换配置挂载位置的已停止网关；项目容器的可写层、工具账号和浏览器数据卷继续使用原资源。

## 迁移 Docker Desktop 数据盘

Docker Desktop 的[官方 WSL 2 说明](https://docs.docker.com/desktop/features/wsl/#turn-on-docker-desktop-wsl-2)提供了通过 Settings → Resources → Advanced 更改位置的入口。迁移整个 Docker 数据盘会影响本机其他软件的 Docker 工作，请先保存这些工作。

1. 点击“检测存储位置”。软件只读取 Docker 设置和数据盘文件；若不能确定实际位置，会明确显示为默认候选位置。
2. 选择专用空目录，例如 `D:\DockerData`，点击“准备迁移”。ENGE SPX 停止自己的工作区，记录现有镜像、容器和数据卷，将目标路径复制到剪贴板，并打开 Docker Desktop。
3. 在 Docker Desktop 点击设置齿轮，进入 **Resources → Advanced → Disk image location**，选择同一个目标目录，点击 **Apply**；有的版本显示 **Apply & restart**。
4. 等待 Docker 完成迁移并恢复运行。返回 ENGE SPX，点击“核验迁移结果”。核验需要目标位置已写入 Docker 设置、该处存在 VHDX，以及原容器、镜像和数据卷都能找到。
5. 重新检查并确认连接。

软件不会修改 Docker 的设置 JSON、注销 WSL 发行版、执行 prune，或自行移动正在使用的 VHDX。Docker Desktop 的设置格式不是稳定公开接口；若版本变化导致位置无法识别，核验会提示“尚未确认”，不会报告成功。原资源存在仅代表资源可见，不等于逐字节校验整个 Docker 数据盘。

## 未完成时如何处理

- **应用数据复制或校验失败**：默认位置不切换，原数据保留。检查目标盘空间、权限和文件占用，再重试。若已生成完整目标副本但写入切换记录失败，先保留原目录，根据错误中路径检查副本，避免重复覆盖。
- **迁移后磁盘未连接**：连接原目标盘后重开软件。软件会报错并保留位置记录，不会自动创建一个空的新环境。可用 `spx --data 完整路径 status` 指定已确认的现有数据目录。
- **旧文件清理失败**：迁移后的目录已经生效，先正常使用新目录；根据 `storage-migration.json` 核对旧文件，再在关闭占用进程后清理。
- **Docker 仍在原位置**：回到 Docker 设置完成 Apply，等待其恢复运行后再核验。ENGE SPX 的“准备迁移”只创建计划，不代表数据盘已经移动。
- **迁移后找不到账号卷或镜像**：先在 Docker Desktop 确认选择了原数据盘并完成迁移。暂勿重新安装环境或创建同名卷，以免把空环境误当成原环境。
